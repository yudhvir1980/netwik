Instance inspection

Reads the ServiceNow instance and compares what is there against what the blueprint says should be there. Costs nothing, writes nothing, and reports which tables the vulnerability flow still has to create.

The second one answers the question the first one raised: do the device records actually carry a software version to match an advisory against, and do the hardware models carry end-of-support dates. Without those, estate matching cannot run.

Match an advisory stage 02

Runs a worked advisory against the live estate and shows the funnel: every device in scope, down to the short list that needs action, with the reason each one left the set. Deterministic code, so it costs nothing and gives the same answer every time.

Data repairs

Three gaps the matcher exposed. Preview reads only and changes nothing. Apply writes to the instance, and needs SERVICENOW_WRITE_ENABLED set to true. Only a fixed allow-list of fields can ever be written.

Exposure

Lifecycle dates
End of sale and end of support on the models the estate uses. Illustrative dates, not real vendor data.
Controller versions
